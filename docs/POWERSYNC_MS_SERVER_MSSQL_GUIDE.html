Production Architecture & Runbook

PowerSync + Microsoft SQL Server Setup Guide

Self-Hosted Offline-First Real-Time Synchronization Architecture for Windows Server & Mobile Clients

1. Architecture & Data Flow Overview

+-------------------------------------------------------------------------------------------------+ | WINDOWS SERVER HOST (e.g. 103.249.198.50) | | | | +------------------------------------+ +-----------------------------------------+ | | | Microsoft SQL Server (2019/2022) | | Docker Engine (C:\powersync\) | | | | Database: SWITCH_Dev | | | | | | | | +-----------------------------------+ | | | | - JobOrder | CDC | | powersync (Core v1.26.1) | | | | | - ServiceOrders |--------->| | - Replicator Engine | | | | | - _powersync_checkpoints | Log Scan | | - CDC Poller (1000ms) | | | | | - SQL Server Agent (CDC Jobs) | Port 1433| | - Router Engine (Port 8080) | | | | +------------------------------------+ | +-----------------------------------+ | | | | | | | | | v | | | | +-----------------------------------+ | | | | | powersync_storage (PostgreSQL 16) | | | | | | - Bucket storage & checkpoints | | | | | +-----------------------------------+ | | | +-----------------------------------------+ | +-------------------------------------------------------------------------------------------------+ ^ | HTTP / WebSockets (Port 8080) | Dynamic JWT (< 86,400s) v +-------------------------------------------------------------------------------------------------+ | FLUTTER CLIENT APPS (Android / iOS) | | - Local SQLite Database (Replicated Views) | | - PowerSync Dart Core 2.4.0 (Offline-First CRUD + Background Sync Stream) | +-------------------------------------------------------------------------------------------------+

PowerSync acts as a high-performance synchronization gateway between your central Microsoft SQL Server and remote client devices. It utilizes SQL Server's native Change Data Capture (CDC) to stream incremental changes in real time (~1 second latency) into a local PostgreSQL bucket cache, which distributes data to connected mobile apps.

2. Phase 1: Windows Server Prerequisites

Mandatory Host Requirements

  • Windows Server: 2019, 2022, or 2025 (or Windows 10/11 Pro for local development).
  • Docker Engine: Docker Desktop for Windows or Docker CE with Docker Compose v2.
  • Microsoft SQL Server: Developer, Standard, or Enterprise Edition (SQL Server Express does not support CDC).
  • SQL Server Agent: Required for executing background CDC log scanning jobs.

Step 2.1: Enable Mixed Mode Authentication

PowerSync connects using SQL Server Authentication. Ensure SQL Server allows both Windows and SQL Logins:

  1. Open SQL Server Management Studio (SSMS).
  2. Right-click the server instance at the top of Object Explorer → Properties.
  3. Navigate to Security → Select SQL Server and Windows Authentication mode.
  4. Click OK and restart the SQL Server service.

Step 2.2: Ensure SQL Server Agent is Running

Run the following command in an administrative PowerShell terminal to start and configure the SQL Server Agent for your instance:

# Check and start SQL Server Agent
Get-Service -Name "*SQL*AGENT*"
Start-Service -Name "SQLAgent$MSSQLSERVER01"   # Use your active instance name
Set-Service -Name "SQLAgent$MSSQLSERVER01" -StartupType Automatic

3. Phase 2: Database CDC & User Configuration (MSSQL)

Execute the following script against your SQL Server instance using PowerShell or SSMS to configure the target database (e.g. SWITCH_Dev):

Step 3.1: Enable CDC on the Database & Target Tables

USE [SWITCH_Dev];
GO

-- 1. Enable CDC on the database
IF (SELECT is_cdc_enabled FROM sys.databases WHERE name = 'SWITCH_Dev') = 0
BEGIN
    EXEC sys.sp_cdc_enable_db;
END
GO

-- 2. Create PowerSync coordination checkpoint table
IF OBJECT_ID(N'dbo._powersync_checkpoints', N'U') IS NULL
BEGIN
    CREATE TABLE dbo._powersync_checkpoints (
        id INT IDENTITY(1,1) PRIMARY KEY,
        last_updated DATETIME2 NOT NULL DEFAULT GETUTCDATE()
    );
END
GO

-- 3. Enable CDC on replicated tables and checkpoints
IF NOT EXISTS (SELECT 1 FROM cdc.change_tables WHERE capture_instance = 'dbo_JobOrder')
BEGIN
    EXEC sys.sp_cdc_enable_table
        @source_schema = N'dbo',
        @source_name = N'JobOrder',
        @role_name = NULL,
        @supports_net_changes = 0;
END
GO

IF NOT EXISTS (SELECT 1 FROM cdc.change_tables WHERE capture_instance = 'dbo_ServiceOrders')
BEGIN
    EXEC sys.sp_cdc_enable_table
        @source_schema = N'dbo',
        @source_name = N'ServiceOrders',
        @role_name = NULL,
        @supports_net_changes = 0;
END
GO

IF NOT EXISTS (SELECT 1 FROM cdc.change_tables WHERE capture_instance = 'dbo__powersync_checkpoints')
BEGIN
    EXEC sys.sp_cdc_enable_table
        @source_schema = N'dbo',
        @source_name = N'_powersync_checkpoints',
        @role_name = NULL,
        @supports_net_changes = 0;
END
GO

Step 3.2: Create Dedicated Replicator User (powersync_user)

CRITICAL GOTCHA: Always specify CHECK_POLICY = OFF, CHECK_EXPIRATION = OFF when creating the SQL login. If left enabled, Windows password expiration or "User must change password at next login" will reject PowerSync connections with ELOGIN: Login failed for user. 
USE [master];
GO

-- 1. Create or reset SQL Login with policy checks disabled
IF NOT EXISTS (SELECT * FROM sys.server_principals WHERE name = N'powersync_user')
BEGIN
    CREATE LOGIN [powersync_user] WITH PASSWORD = 'SwitchFiberPS2026', CHECK_POLICY = OFF, CHECK_EXPIRATION = OFF;
END
ELSE
BEGIN
    ALTER LOGIN [powersync_user] WITH PASSWORD = 'SwitchFiberPS2026', CHECK_POLICY = OFF, CHECK_EXPIRATION = OFF;
END
GO

ALTER LOGIN [powersync_user] ENABLE;
GRANT CONNECT SQL TO [powersync_user];
GO

-- 2. Grant access in the target database
USE [SWITCH_Dev];
GO

IF NOT EXISTS (SELECT * FROM sys.database_principals WHERE name = N'powersync_user')
BEGIN
    CREATE USER [powersync_user] FOR LOGIN [powersync_user];
END
GO

ALTER ROLE [db_owner] ADD MEMBER [powersync_user];
GRANT VIEW CHANGE TRACKING ON SCHEMA::dbo TO [powersync_user];
GRANT SELECT ON SCHEMA::cdc TO [powersync_user];
GO

Step 3.3: Initialize the Initial CDC LSN Boundary (Crucial Step)

CRITICAL GOTCHA: When CDC is first activated, cdc.lsn_time_mapping contains 0 rows, causing sys.fn_cdc_get_max_lsn() to return NULL. In PowerSync, this triggers TypeError: Cannot read properties of null (reading 'length') at LSN.fromBinary. To fix this permanently, write one transaction and force an immediate log scan: 
USE [SWITCH_Dev];
INSERT INTO dbo._powersync_checkpoints (last_updated) VALUES (GETUTCDATE());
EXEC sys.sp_cdc_scan;

-- Verify that max_lsn is now populated (non-null)
SELECT count(*) AS lsn_mapping_count FROM cdc.lsn_time_mapping;
SELECT sys.fn_cdc_get_max_lsn() AS max_lsn;

6. Phase 5: Troubleshooting & Comprehensive "Gotchas" Runbook

Error / Symptom Root Cause Exact Solution
PSYNC_S2302 (500)
No sync config available		 The replicator skipped activating the sync stream because processingConfig.sync_rules_content == loadedSyncRules failed due to Windows CRLF (\r\n) vs Linux LF (\n) string differences. Embed sync rules directly inline inside service.yaml under sync_config.content with an explicit version_label: 'v1'. Run docker compose down -v to clear stale postgres rows.
Failed to update sync config
Unknown function		 Functions like CONCAT(), COALESCE(), or ISNULL() are not supported in PowerSync sync rule queries. Use SQLite-standard || concatenation syntax: FirstName || ' ' || LastName AS customer_name.
ELOGIN
Login failed for user 'powersync_user'		 SQL Server in Windows Authentication only mode, user password expired / locked by policy, or password in docker-compose.yaml has special delimiter characters (like !). Use an alphanumeric password like SwitchFiberPS2026. Execute ALTER LOGIN [powersync_user] WITH PASSWORD='...', CHECK_POLICY=OFF, CHECK_EXPIRATION=OFF; and enable Mixed Mode authentication.
TypeError
Cannot read properties of null (reading 'length')		 sys.fn_cdc_get_max_lsn() returned NULL because CDC was newly enabled and no transactions had been logged in cdc.lsn_time_mapping. Run: INSERT INTO dbo._powersync_checkpoints (last_updated) VALUES (GETUTCDATE()); EXEC sys.sp_cdc_scan; to populate the initial LSN.
PSYNC_S2104 (401)
Token must expire in a maximum of 86400 seconds		 Client JWT token was signed with an expiration longer than PowerSync's strict 24-hour limit (86,400 seconds). In Flutter backend connector, sign tokens with a lifetime of 23 hours: DateTime.now().toUtc().add(const Duration(hours: 23)).
Multi-Instance Conflict
SQLSERVERAGENT cannot start		 The server has multiple SQL instances (e.g. default MSSQLSERVER stopped, but named instance MSSQLSERVER01 active). Check active services with Get-Service -Name "*MSSQL*". Ensure the active instance's agent (e.g. SQLAgent$MSSQLSERVER01) is set to Automatic and Running.

Step 7.3: Dynamic Client JWT Signing (HMAC-SHA256)

In lib/core/sync/powersync_backend_connector.dart, dynamically generate the JWT with a 23-hour lifespan:

import 'dart:convert';
import 'package:crypto/crypto.dart';
import 'package:powersync/powersync.dart';

class SwitchFiberBackendConnector extends PowerSyncBackendConnector {
  @override
  Future<PowerSyncCredentials?> fetchCredentials() async {
    final now = DateTime.now().toUtc();
    final expiresAt = now.add(const Duration(hours: 23));

    final header = base64Url.encode(utf8.encode(jsonEncode({
      'alg': 'HS256',
      'typ': 'JWT',
      'kid': 'dev-key'
    }))).replaceAll('=', '');

    final payload = base64Url.encode(utf8.encode(jsonEncode({
      'sub': 'technician@switchfiber.ph',
      'aud': 'powersync',
      'iat': now.millisecondsSinceEpoch ~/ 1000,
      'exp': expiresAt.millisecondsSinceEpoch ~/ 1000,
    }))).replaceAll('=', '');

    final secretBytes = utf8.encode('switchfiber_powersync_dev_secret_key_2026');
    final hmac = Hmac(sha256, secretBytes);
    final signature = base64Url.encode(hmac.convert(utf8.encode('$header.$payload')).bytes).replaceAll('=', '');

    final token = '$header.$payload.$signature';
    return PowerSyncCredentials(
      endpoint: 'http://103.249.198.50:8080',
      token: token,
      userId: 'technician@switchfiber.ph',
      expiresAt: expiresAt,
    );
  }
}
